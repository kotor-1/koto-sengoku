## 1. 味方同士の詰まり（仕様の決定）

- **1 か所の定義：** `RULES.allyBlockSec`（既定 2 秒。調整できる初期値）。今の `squeezeHoldSec`（12 秒）の決まりは、これに置き換える。
- **順番：**
  1. 行き先へ進めない原因が「味方だけ」かを見る（壁・閉じた門・深い川・崖・敵部隊で塞がれているなら、味方のすり抜けは使わない）。
  2. 短い通れる迂回（道探しで、味方の隊の周りを避けた道の長さが直線の道の 1.5 倍以内などのデータ）があれば、それを先に使う。
  3. 味方だけに塞がれた状態が allyBlockSec 続いたら、味方同士の通過の調整を始める（動いている側が、味方の中をすり抜ける）。
     - 防衛・待機を命じた味方は動かさない（すり抜ける側が通るだけ）。
     - 狭路の同時交戦数の制限（narrow_frontage）は保つ（すり抜けは斬り合いの数に入れない／順番待ちは変えない）。
  4. 物理的に道が無い（味方が退いても通れない）ときは、すり抜けさせず、理由を案内に出す。
- **確認：** 村落の再現ケース（石川隊が酒井隊の後ろで止まった場面）で、長く止まらず辻へ進むこと。e2e の「10 秒以上動かない部隊なし」はそのまま（緩めない）。

## 2. 操作と配置の残件

- **能力の説明の欄：** 押し・なぞり（スクロール）は欄で使い切り、下の戦場への移動・攻撃にしない。操作の要らない知らせ（押しを地図へ通す）とは別の扱いにする。
- **移動先指定の素早い 2 回：** 意図しない選び直しと能力の発動を起こさない（2 回目は同じ点の移動の重ね、または何もしない）。
- **閉じた門の先への移動：** 目的地と「開門待ち」を命令に持たせる（例：`order.awaitGate = gateId`）。
  - 門が開いたら道を引き直して続ける。
  - 新しい命令で、古い保留は捨てる。
  - 札・案内に「開門待ち」と出す。
  - 敵への攻撃の可否や射線の判定とは別。
- **城下町外縁：** 味方の退き口と敵の突破口を離す。地図の名札と説明で用途を分ける（「味方の退き口」「敵の突破口」）。
- **上の知らせ：** 重要な名札（選択中・点滅中）を覆うときは、知らせを畳むか、位置を変える。選択と発動を妨げない。

## 3. 終了の判定の優先順位（共通）

- **目標の種類の追加：**
  - `escape { unitIds?, hq: true, count, exits: Zone[] }`：総大将と指定数の部隊が出口から離れる。
  - `rescue_escort { unitId, meetZone, safeZone, minRatio }`：合流してから安全地点まで。生存と最低兵力の条件つき。
  - `withdraw { hq: true, count, exit }`：退き口から離脱。
  - `capture_zone { zone, sec }`：敵の拠点の制圧。今の hold_point でよければ使う。
- **判定の順番：** 戦場ごとにデータで明示し、説明（合戦の前・結果）に出す。
  1. 主目標の達成（脱出・救出・撤収）→ 勝利。
  2. 主目標が果たせなくなった（救出の対象が崩れた・総大将が討たれた／敗走した、など）→ 敗北。
  3. 通常の本陣の喪失（総大将が出口から離れた場合は「脱出」で、喪失ではない）。
  4. 日没 → 撤退（ただし主目標の段階に応じた記録）。
  5. 全軍撤退の命令：退却の目標がある戦場では、命令した部隊も出口の判定に入る。目標の達成前に、合戦を打ち切らない。
- **区別：** 単なる合戦の放棄（全軍撤退の命令で目標の前に退いた）と、目標を果たした撤収は、記録と説明で分ける。
- **記録：** 主目標・副目標・約束・勝敗を別々に記録する。

## 4. 共通の機能の追加

- **演習の追い討ち：** 戦場データの `pursuit: true`（今の歴史分岐の追い討ちを、データで演習にも使えるようにする）。退却戦・包囲された陣で使う。
- **夜（視界と発見）：**
  - 戦場データの `night { sight: number; detectRange; torchZones? }`。
  - 敵と味方それぞれに「発見済み」の状態を持ち、発見していない相手は狙わない・追わない。
  - 画面では、発見していない敵の名札・位置・兵士・札を出さない（開発用の窓の変数でも出さない形を検査）。
  - 篝火の区域・物見（敵の見張り）で発見されやすさが変わる。
  - 発見の後は普通に戦える。
  - 画面の暗さは、色を少し落とす程度（新しい照明や美術は作らない）。
- **水辺：** 今の river（通れない水面）を一方の端に置き、岸沿いの狭い道と内陸の迂回路・高地を作る（新しい地形は要らない見込み）。
- **部隊数の検査：** 救出の対象と増援を、同時に存在する部隊数（味方 8・敵 10）に含めて検査する（今の validateField を確かめる）。

## 5. 第4群の 5 戦場（演習の一覧に足す。合わせて 20 戦場）

| id | 名称 | 主目標 | 地形・配置の要点 | 成り立たせたい作戦 |
|---|---|---|---|---|
| besieged_camp | 包囲された陣 | 総大将と指定数（例：3）の部隊が、包囲の外の出口から脱出 | 中央の陣から始まり、敵は 3〜4 方向。短いが厚い突破口と、回り道で手薄な突破口 | 先に突破口を開いてから総大将を出す、厚い口を準備して破る（速い・損害大）、手薄な回り道（遅い・追われる） |
| relief | 援軍救出 | 孤立した味方と合流し、安全地点まで退かせる（対象は兵 N 割以上で生きていること） | 合流地点と安全地点が別。対象を囲む敵と、途中の敵 | 急いで直接救う、敵の一部を引き離してから救う |
| rearguard | 退却戦 | 総大将と必要な部隊（例：4）を退き口から離脱させる | 敵が実際に追う。退き口までの狭い道、殿の置き場所 | 殿を置いて順番に退く（忠勝の守護は役に立つが、必須ではない）、全軍で一気に退く（追い討ちで崩れる） |
| night_raid | 夜襲・奇襲 | 夜に指定の敵拠点を制圧（区域を一定秒） | 近いが篝火・物見の厚い道、長いが見つかりにくい林と畦の道 | 隠れて近づく、見つかってから戦って取る |
| shore | 湖・河岸 | 補給路の二つの要所を一定時間維持（同時でなくてよい／defend_zones などをデータで） | 一方が湖、岸沿いの狭い道（近道）、内陸の迂回路と高地 | 岸の近道を固めつつ、内陸の高地に予備を置いて横からの攻めに備える |
