# Version 25：会話・軍議の半身の立ち絵と、合戦の顔を同じ個別原画へ

依頼（2026-10-10）：添付の素材パック第 2 版（個別原画 `sengoku_individual_art_v2`。ZIP 3 つ）と、パックの中の最初に読む案内（START_HERE の txt）に従って進める。
Version 24 までの成果と保存を守り、まず人物の半身の立ち絵を会話・軍議に組み込み、合戦の顔アイコンも同じ原画にそろえる（小さな顔の差し替えだけで終わりにしない）。
背景は原寸 1672×941 で 1920px 幅の要件に届かないので、原寸以内で出せる画面だけで比べる（背景の制限で人物の組み込みを止めない）。
必要な画像だけを公開し、原画の ZIP をゲームの配信フォルダに入れない。旧表示へ戻せる比べる版として出す。

この文書が Version 25 の組み込みのまとめ（組み込んだ物・決まり・公開する物・確かめた事・残っている事）。素材 1 件ごとの記録は docs/art-assets.md、
出どころと利用条件は docs/third-party-assets.md の「sengoku_individual_art_v2」、素材の取り込みの道具は docs/art-v22-structure.md と
proto3d/assets-src/art-v25/README.md、台詞の枠の顔は docs/art-v22-dialog-face.md。

変えていない物：物語の文・選択肢・約束・保存（新しい localStorage の鍵も無い）・合戦の計算・地形・移動・20 戦場・第二章の流れ・音・CSP・
3D の人物のモデル（頭の形などは良くなっていない）・草地・土・道の地面・スマホの台詞の字（15px・16px）・Version 24 の狭い画面の選択肢の直しと入力の守り。

## 3. 行ごとの出し方（`ui/artCanvas.ts` の `portraitStep`・`PortraitSlot`）

- 絵のある人の行：その人の絵を左下に出す（話し手が変わると 140ms で重ね変わる。動きを減らす設定では、すぐ）。
- **絵の無い話し手（使者・村の使い・知らない話し手）・地の文・高札の行は、前の人の立ち絵を下げる**（Version 22〜24 の「暗く残す」をやめた）。
  作業 B の数え上げでは、暗く残っていた 37 の行はすべて酒井・石川の軍議の行で、忠勝（か家康）の大きな絵が残ったまま別の人の顔が台詞の枠に出ていた。
  Version 25 で酒井・石川にも本人の絵が付き、残る「絵の無い話し手」は使者・村の使いだけ。そこで前の人の絵を残すと、家康・忠勝が使者の言葉を話しているように見えるので、下げる。顔も出さない。
- 立ち絵が出ている行は、その人の台詞の枠の顔を出さない（同じ人を大小 2 つ並べない。`dialogFaceFor`）。立ち絵が入りきらない画面・行・読めなかった時は顔が出る。
- 読めない時：立ち絵だけ読めなければ顔が出る。顔だけ読めなければ台詞の枠は Version 21 のまま（`e2e/dialog-face.mjs` の failportrait・failface）。
  全部読めなければ Version 21 と同じ会話の画面（名前・台詞・選択肢・操作は残る）。

## 4. 大きさと置き方（`portraitLayout`・`PORTRAIT_RULES`）

- 左下に置き、下端は画面の下の端（腰から下は台詞の枠の後ろ。枠の中は透明に抜く＝台詞の字の後ろに絵が透けない）。左右の反転はしない。
- Version 27：軍議の背景を画面より小さく描いている間（2560×1440 など）は、画面の代わりに描いた背景の所を元にする（高さは描いた所の 86%・下端は描いた所の下端・腰の切り口を背景の縁と同じになじませる。13）。
- 一番大きくできる大きさ：画面の高さの 86%（高さ 430 以下は 80%）。Version 22〜24 の上限（PC 620px・スマホ横 300px）は外した。
- 重ねない物：選択肢（並びを収め直した時も測り直す）・軍議の見出し（文字の箱。Version 25 は背景が出ている間の後ろの暗さも含めたが、
  Version 26 から含めない：背景の有無で立ち絵の大きさを変えない。下の 5）・詳しく見る・メニュー・目的の札・情勢。
  「幅で避ける」か「高さで避ける」かの大きい方までは広げる。
- **元の画像を拡大しない**：高さは「画像の高さ ÷ 端末の画素の比」まで（例：家康 1532px は、端末の比 2 で 766px、3 で 510px まで）。
  canvas は端末の比 3 まで端末の画素で描く（元の画像の画素より細かくはしない）。
- **頭・髷・肩を隠さない**：台詞の枠が立ち絵と横に重なるなら、枠の上端より上に、肩が見え切る所（素材ごとの `shoulderY`）まで見えていること。
  見えなければ出さない（小さくすると上端が下がって見える割合が減るので、縮めない）。`shoulderY` は `art-build.py set-anchor` で原画の画素の座標として記録し、
  加工版の割合に直して `manifest.gen.json` の meta に入る（原画の無い clone でも記録が残る）。値は人の形の幅が胸の上で最大の幅の 75% に届く行（肩の線より下）：
  家康 0.431・忠勝 0.452・酒井 0.421・石川 0.410（画像の上から。公開していない榊原 0.459・長政 0.397 は正本の記録にだけ残す）。画像には髷の上に 8px の余白があり、頭の上は切らない。
- 出さない画面：高さ 340 未満（568×320 など）・左下の空きの幅 150 未満・高さ 210 未満・上の肩の決まりを満たせない。そのときは台詞の枠の顔だけ。
- 位置は absolute：出ても下がっても、遅れて読めても、台詞・名前・選択肢の位置は動かない（Version 24 と比べて 0 の違い）。

測った値（2026-10-11・開発サーバー・本物の素材・本物の入力。`e2e/portrait-v25.mjs` の 6 つの大きさ × 第一章・第二章。768×1024・568×320 は作業 C の同じ確かめ）：

## 5. 軍議の背景（`CouncilBackdrop`・`councilArtLayout`。Version 26 で決まりを変えた）

依頼（2026-10-11、Version 26）：「低解像度画像を拡大して高解像度原画と称すること」は禁止のまま、表示の時の軽い拡大まで一律に禁じる条件は外す。
1664×936 の背景を 1920×1080 に表示する約 1.15 倍の拡大は比べる物として認める。原画の寸法と表示の寸法は分けて記録する。
端末の画素の密度だけを理由に背景を外さず、実際の表示の範囲で画質を確かめる。大きすぎる拡大が要る画面は、表示の範囲を限るなどで対応する。
文字・操作を背景の画像に描き込まない。背景と人物の比を保ち、引き伸ばして形を変えない。旧背景（Version 24 の軍議の画面）へ戻せる比べ方は残す。

**決まり**（`ui/artCanvas.ts` の `COUNCIL_ART`・`councilArtLayout`）

- 表示の倍率 ＝ 描く CSS の px ÷ 元の画素。画面（CSS の px）を cover で埋め（上下は 18% まで切る。それ以上の横長の画面は左右に暗い帯）、
  その倍率を **1.25 倍まで**にする。**端末の画素の比（devicePixelRatio）は使わない**（端末の比 2・3 の画面でも、それだけでは外さない・縮めない）。
- 1.25 倍を超える画面（2560×1440 は 1.538 倍が要る・タブレットの縦 1024×1366 は 1.459 倍）は、**外さず、引き伸ばさず、1.25 倍で真ん中に描き**、
  周りは暗い地（`#0e0c0a`。Version 25 までの横長の画面の帯と同じ色）にする。絵の縁は暗い地へなじませる（帯のある向きだけ。
  幅は描いた絵の短い辺の 7%・24〜110px で、帯が細いときは帯の 2 倍まで）。縦横はいつも同じ倍率（形を変えない）。
- 縦向きのスマホ（素材の幅の 25〜32% しか見えない）は、素材の真ん中（柱・陣幕・梁）を見せる（`focusX` 0.5。下の 5a）。
- canvas は描く所だけの大きさで、画素は元の画像の切り出しの画素まで（端末の比 2 まで）。展開した画像（約 6.2MB）のほかに持つのは、
  多くても 1664×936 の canvas（約 6.2MB。縦向きのスマホは 433×936 で約 1.6MB）。
- 文字・ボタン（見出し・台詞・名前・選択肢・詳しく見る・メニュー）は今までどおり DOM で、背景の画像には描き込まない。背景は層のいちばん奥・立ち絵と文字の後ろ。
  見出しの後ろの薄い暗さ（`.g-art`）・弱い周辺の暗さ・手前の幕の揺れ（無し：手前の幕はまだ届いていない）・動きを減らす時の決まりは Version 25 のまま。
  ただし高さ 430 以下の画面だけ、見出しの後ろの暗さを少し濃くした（形・大きさは同じ。背景を縦に切るので明るい陣幕が見出しの後ろに来るため。下の 5a）。
- **立ち絵・台詞の枠の顔・台詞の字の大きさと位置は、背景の有無で変わらない**（`e2e/council-bg-v26.mjs` で `?artOff=council` と比べた。下の 5a）。
  Version 25 は、立ち絵が見出しの後ろの薄い暗さ（`.g-art` の `::before`。見出しの箱の上 8・左右 34・下 10px 外まで）も避けていたので、
  背景が出る画面では立ち絵が小さくなる所があった（Version 25 自身も、背景を出していた 667×375@2・640×360@2 では 288・273 で、背景の無い @3 の 300・288 より小さい。
  その決まりのまま背景をどの画面でも出すと、360×640@2 で 540→536・320×568@2 で 474→464・667×375@3 で 300→288・640×360@3 で 288→273 に縮む）。
  背景をどの画面でも出すと、Version 25 で背景の無かったスマホの画面の立ち絵が縮むので、Version 26 では立ち絵は見出しの**文字の箱だけ**を避け、
  DOM では見出しの後ろ（選択肢の前）に置く（暗さの上に描かれ、立ち絵は暗くならない。文字の箱とは重ならない）。立ち絵の大きさは、どの画面でも背景を出さない時
  （`?artOff=council`・Version 25 の背景の無かった画面）と同じ。
- 読み込み：Version 25 は「原寸以内の画面だけ読む」だったが、Version 26 はどの画面でも出すので、忠勝との会話の間と軍議の始めにいつも読み始める。
- 窓の大きさ・向きが変わったら描き直す（表示の範囲を限る・限らないも決め直す）。層の大きさが測れない（0）間は出さない。

## 7. 読み込み（`art/registry.ts`）

- 城下で操作できるようになった時に主人公と城下の人の立ち絵・顔を、「話す」が出た時にその相手の分を、会話・軍議を開いた時にその台本の話し手の分を、先に読み始める。
  軍議の背景は、忠勝との会話の間と軍議の始めに読み始める（Version 25 は原寸以内の画面のときだけ。Version 26 からはどの画面でも出すのでいつも）。遅く読む・先に読むは「いつ読むか」で、公開するファイルの総量は減らない。
- 読めない（通信の失敗・HTTP の誤り・時間切れ・壊れた画像）とき：その絵は出さず（名前・台詞・選択肢・操作はそのまま）、前の失敗から 10 秒たった後に
  その絵を使う行が来たら読み直す（ずっと出ないままにはしない）。警告（console.warn）は ID ごとに 1 回。
- **時間切れは「通信が進まない時間」に掛ける（30 秒）**：返事・中身の一切れが届くたびに数え直すので、遅い回線でも届き続けている読み込みは止めない。
  見張りの時計が遅れて鳴った（ページが 3D の組み立てなどで塞がっていた）ときは、すぐ止めず、届いている中身を受け取る 1 秒をおいて決め直す。
  画像の展開（createImageBitmap）は数えない。
  （Version 25 の最後の確かめで見つけて直した：本番ビルドの e2e（1280×720・負荷 9〜23 のソフトウェア描画）で「[art] … を読めませんでした AbortError」が出ていた。
  原因は、30 秒の時計を通信の全体（fetch と中身の受け取り）に掛けていたこと。ページの中の見張りで測ると、主の処理が 1 回 20〜34 秒塞がり、
  中身は届いていても（Playwright では 6〜9 秒で通信が終わっていた）受け取りが 30 秒に間に合わず止めていた。遊ぶ人でも、遅い回線で届き続けている読み込みを
  30 秒で捨てて最初から読み直す・重い端末で 3D の組み立ての間を通信の時間に数える、が起こりうるので直した。読めなかった絵は 10 秒後の行で読み直されていて、
  会話の文字・選択肢・操作はどの行も残っていた。単体テスト `tests/proto3d-art-manifest.test.ts` の「時間切れ」の 4 件）

### 12.1 修正 1：選択肢を押している間に画面が回った・並べ方が変わったら、その押しを取り消す（78ee1ca）

- 対象：縦に動く選択肢の並び（Version 24 の狭い画面。押した瞬間でなく、指を離した時に決める並び）。

  - 窓の `resize`・`orientationchange`・`screen.orientation` の `change`・`visualViewport` の `resize`（`ui/dom.ts` の `screenChanges`）
  - 選択肢の並びの収め直し（`ui/choiceFit.ts` の `ChoiceFit.layouts`。台詞の枠の高さが変わった時など）
  - 押したボタンの四角が 1px より動いた・大きさが変わった（`ui/guard.ts` の `PRESS_SHIFT_PX`・`samePlace`。出来事が遅れて届く時の控え）
- 会話の位置（同じ台本・同じ行）・選択肢・選んでいる印・並びの位置はそのまま（収め直した後も選んでいる物を見える所へ動かす）。
- 変えていない物：動かない並び（押した瞬間に決める。PC・スマホ横・縦長でも並びが収まる画面）・キーボード・押し始めの 350／140ms の守り・
  メニューや「詳しく見る」が上にある時の押し・なぞり（10px）・`pointercancel`。`?art=v24`・`?art=old` も同じコードで同じ守り。
- コード：`ui/guard.ts`（`PRESS_SHIFT_PX`・`PressPlace`・`samePlace`・`TapTracker.up`）・`ui/dom.ts`（`countEvents`・`screenChanges`・`onPress` の `layoutOf`）・
  `ui/choiceFit.ts`（`layouts`）・`ui/view.ts`（選択肢のボタンに `layoutOf` を渡す）。単体テスト `tests/proto3d-ui-guard`・`proto3d-ui-press`・`proto3d-ui-press-screen`・`proto3d-ui-choice-fit`。
- 直す前（Version 25 のコード・開発サーバー・本物の CDP のタッチ）：360×640・640×360・568×320・320×568 で方針 A を押したまま回す・窓の高さを変える・

- 直した後：下の 12.4。押したまま回す・高さを変える・収め直すは、指が回した後も同じ選択肢の上にあっても決まらない。改めてたたけば 1 回だけ決まる。

  ↓ で並びの形が変わらず、指の下のボタンも動かないため）。画面の回転・並べ方の変化ではなく、指とキーボードを同時に使う場合だけなので、そのままにした。

## 13. Version 27：範囲を限って描いた軍議の背景に、立ち絵の大きさと位置を合わせる

依頼（2026-10-13、Version 26 の報告を受けて）：12.3 の判断待ちの 3 択のうち「描いた背景の高さに合わせて立ち絵を抑える」を採用。背景を画面全体ではなく
