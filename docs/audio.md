# 音（BGM・環境音・効果音・声）：作り方・設定・確かめ（Version 21）

依頼：docs/v20-feedback-request.md【3】〜【6】。コード：`proto3d/src/audio/`（音の土台・曲・効果音・声・設定）、

## 1. 何を作ったか

| 種類 | 中身 | どこで鳴るか |

| BGM「急報」 | 都節の音階（E・F・A・B・C）、66 BPM。尺八のような息の旋律・低い箏の和音と刻み・大太鼓の鼓動と連打。段 A → B（高まる）→ A′（箏の刻み）の 24 小節（約 87 秒） | 冒頭の急報（使者・家臣の報告）・第二章の冒頭の使い・軍議・情勢の図解・負けて帰る演出 |
| BGM「合戦」 | 民謡の音階（D・F・G・A・C）、136 BPM。始めの法螺と太鼓（2 小節）の後、笛の旋律・箏の刻み・大太鼓・締太鼓・鉦の A → B → C（太鼓の掛け合い・法螺）の 20 小節（約 35 秒）を繰り返す | 出陣の演出・合戦の画面（読み込みの待ちを含む） |

| 合戦の効果音 | 刃の当たり（金属の響き）・矢（風切りと当たり）・太鼓（ぶつかり・敗走・能力）・法螺（始まり・終わり） | 合戦 |

- 和風を意識したオリジナル：五音の音階・はじく弦（箏）・息の音（篠笛・尺八の気分）・太鼓・鉦・拍子木・法螺を、すべてこのコードの合成で作った。
  既存のゲーム・ドラマの曲や録音・音源のファイル・購入・外注・有料 API は使っていない。楽譜も新しく書いた物（`audio/songs.ts`）。
- 電子音の警告音のような単音の繰り返しにしない：どの曲も旋律・伴奏・打楽器の 3 層があり、段ごとに旋律・伴奏の型・打楽器の型が変わる
  （テスト：`楽譜：旋律・伴奏・打楽器と段の変化`）。

## 2. 作り方

### 音の土台（`audio/engine.ts`）

- AudioContext は 1 つ。マスター（ミュート）→ 圧縮（割れ止め）→ 測り（AnalyserNode）→ 出力。マスターの前に BGM（音量 × ダッキング）・声・効果音／環境音の 3 つのバス。
- 有効にする時：最初の利用者の操作（タップを離した・クリック・キー）。タイトルの「はじめから」「つづきから」を押すと、その操作で有効になる。
  それまで AudioContext は作らない。音を出すためだけの設定画面は無い。
- 失敗しても進む：AudioContext を作れない・始められない・読み上げが無い・投げる、のどれでも進行は止めない（字幕は残る。テスト：`有効にする・失敗しても進む`）。
- アプリの切り替え（visibilitychange で隠れた・pagehide・blur）：AudioContext を一時停止（suspend）し、声を止める。戻った（見えていて窓が前）ら再開する。
  演出の再生器（`ui/cinePlayer.ts`）も同じ時に自動で一時停止する（演出は「再開」を押すまで止めたまま）。戻ったときに声を読み直さない・止めていた間の音をまとめて鳴らさない。

### BGM（`audio/songs.ts`・`audio/music.ts`・`audio/instruments.ts`）

- 楽器：箏は、はじいた弦の物理のまね（Karplus–Strong）を音の高さごとに 1 回だけ AudioBuffer に書いて使い回す。笛・尺八は正弦波＋三角波に、音の高さの帯の息の雑音・遅れて掛かる揺れ・立ち上がりのしゃくり。
  太鼓は高さの落ちる正弦波と短い雑音、鉦・拍子木は数本の正弦波、法螺はのこぎり波を貝の響きの帯（formant）に通す。
- 鳴らし方（描画のコマに比例しない）：
  1. 描いた輪（既定）：曲ごとに 1 回、OfflineAudioContext で 1 周分（＋鳴り残り 3.5 秒）を 24 kHz・単音で描き、鳴り残りを輪の頭に重ねて継ぎ目を消し、
     AudioBufferSourceNode の繰り返し（loopStart〜loopEnd）で鳴らす。描くのも鳴らすのも音の処理の側なので、描画が重い・止まる（読み込み・合戦の画面の組み立て）間も途切れない。
     有効になった後、今の曲から 3 曲を 1 曲ずつ描く（3 曲で約 210 秒分 × 24 kHz × 4 バイト ≒ 20 MB のメモリ。ファイルは増えない）。
  2. 先読みの予約（描き終わるまで・OfflineAudioContext の無い端末）：setTimeout（50 ms ごと）で起き、AudioContext の時刻から 2 秒先までの音を予約する。
     描き終わったら、同じ曲の同じ位置から輪へ受け渡す（予約の音は 0.3 秒で消す）。タイマーが遅れた・止まった後は、過ぎた音を捨てて次の小節から続ける（まとめて鳴らさない）。
- 曲の切り替え：前の曲を 0.8 秒でフェードアウトし、新しい曲を 0.35 秒後から 0.6 秒でフェードイン。同じ曲を選び直しても始め直さない。切り替えの後に鳴り続けるのは 1 曲だけ。
- 声の間は BGM を 0.32 倍に下げる（ダッキング。読み始めで下げ、終わり・止めたら戻す。終わりの知らせが来ない端末のため、長さの見込み＋2 秒でも戻す）。
- 曲の大きさ：オフラインで描いた音の RMS で 3 曲をそろえた（城下 −20 dBFS・急報 −18 dBFS・合戦 −15.5 dBFS。既定の BGM の音量 60% のとき）。

### 環境音・効果音（`audio/sfx.ts`）

- 足音：`FootstepTracker` が、進んだ距離から決まる位相（stride の合計）の半周ごとに 1 歩を返す。速さ 0.3 m/秒未満は鳴らさない（止まると鳴らない）。
  素材の足が着く位相を骨から測った（歩き：0.05 と 0.51 付近、走り：0.99 と 0.49 付近）ので、鳴らす位相は 0.02 と 0.52（差は 0.04 周期以内＝歩きで約 40 ms）。
- 荷の作業：0.7〜2.5 秒ごとに、聞く位置（探索のカメラ）と荷置き場（−7.8, 10.6）の距離で大きさを決めて鳴らす（16 m より遠いと鳴らさない。左右にも振る）。
- 合戦：斬り合っている部隊の数・射っている部隊の数から 1 秒あたりの見込みを決め（上限：刃 5・矢 3）、`VoiceLimiter` で同時に 4 つ・1 秒に 6 つまでに制限する。
  ×2 では 1 秒の数を 0.6 倍にする（間引く）。指揮（一時停止）・結果の間は鳴らさない。ぶつかり・敗走・能力の太鼓は別に同時 2・1 秒 3 まで。見えていない敵の出来事では鳴らさない。

### 声（`audio/voice.ts`・`audio/readings.ts`）

- 方式（暫定）：端末の日本語読み上げ（Web Speech API の speechSynthesis）。**端末に依存する**。端末に日本語の声が無いと声は出ない（字幕は出る）。
  メニューの音の欄に「声は端末の日本語読み上げを使います。端末に日本語の声が無いと声は出ません（字幕は出ます）。」と書いた。
  端末に日本語の声が複数あるときは、男性の声らしい名前（Otoya・Ichiro など）を先に選ぶ。人物ごとに高さ（0.72〜1.2）と速さ（0.94〜1.1）を少し変える。特定の俳優・作品の声はまねていない。
- 第一候補の VOICEVOX Nemo を使わなかった理由：配布元（voicevox.hiroshiba.jp・github.com）がこの環境の社内の代理で拒否（403）された。回り道・再試行はしていない。
  PyPI の pyopenjtalk-plus は入れられるが、入っている声が女性の声 1 つ（HTS Voice "Mei"）だけで、主要人物（家康・忠勝・数正・使者）に合わないので使わなかった。
- 読む台詞：台詞の表（担当 I）の 26 行だけ（全会話の読み上げ・口パクはしない）。演出の字幕は `voice`（台詞の id）を持ち、会話の行は話し手と文で表を引く。
  **字幕と声の言葉は同じ**：読み（音声用のかな）は id ごとに「どの表示の文に対して書いたか」と一緒に持ち、表の文が変わるとテストが読みの書き直しを求める。
  読みは漢字をかなに開くだけ（言葉は変えない。表の文のかなの続き 3 字以上は読みにもそのまま入る：テスト）。
- 読みを確かめた語：家康（いえやす）・忠勝（ただかつ）・数正（かずまさ）・本多（ほんだ）・石川（いしかわ）・浅井（あざい）・朝倉（あさくら）・長政（ながまさ）・
  元亀（げんき）・三河（みかわ）・近江（おうみ）・後備え（あとぞなえ）・小荷駄（こにだ）・殿（「殿、軍議を」→との・「徳川殿」→とくがわどの）・退き口（のきぐち）・
  後詰め（ごづめ）・先駆け（さきがけ）・拙者（せっしゃ）・主（あるじ）・皆（みな）・退け（ひけ）。表の台詞の読みには、これらの漢字を残さない（テスト）。
  今の表に「しんがり」の意味の殿は無い（入ったら、その台詞の読みに書く。辞書では開かない）。
- 止め方：読む前に必ず前の声を止める（cancel。待ち行列を作らない：同時に 2 人が話さない）。行を送る・字幕が替わる・演出のスキップ・前／次の場面・一時停止・
  演出の終わり・会話を閉じる・タイトルへ戻る・合戦の画面に入る・アプリの切り替え・ミュートで止める。止めた声は後から読まない。
- 合戦の掛け声（全軍撤退・能力の発動。味方の武将だけ）：読めるときは、読む前に同じ文を字幕（上の真ん中の `.b-voicecap`）に出す。×2 でも声の高さ・速さは変えない。

## 3. 設定

- メニュー（探索・会話・軍議の途中の「メニュー」・M）の下に小さく「音」の欄：ミュート（チェック）と、BGM・声・効果音／環境音の音量（0〜100、5 刻みのつまみ）。
- 保存：保存の外の小さなキー `koto-sengoku/3d-audio`（`{ v:1, muted, bgm, voice, sfx }`）に、**利用者が変えたときだけ**書く。
  章の保存（`3d-chapter1`・`3d-ieyasu1570`（＋`/previous`・`/chapter1`）・`3d-fields`・2D 版の `koto-sengoku/save`）と演出の設定（`3d-prefs`）には触れない。
  読めない・壊れている値は既定（ミュートなし・BGM 60・声 90・効果音 70）。書けない端末でも、その遊びの間は効く。
- 音量のつまみは 2 乗の曲線（BGM・効果音）。声は読み上げの volume（0〜1）。

## 4. 容量・配信・セキュリティ

- 音のファイルは 1 つも足していない（0 バイト）。すべてコードの合成。足したのは JavaScript だけ（本番ビルドの増え方は §6 の記録）。
- 描いた輪はメモリの中だけ（約 20 MB）。遅延読み込みで公開の総容量が減る扱いにはしていない（そもそも足した素材が無い）。
- CSP（e2e/ieyasu-prod.mjs と同じ）を緩めていない：音の欄の見た目は `<style>`（style-src 'unsafe-inline' は前から許可）、外の通信・Worker・blob の読み込みは無い。
- 既存の素材の読み込み（.json の素材と glb-to-gltf）には触れていない。

## 5. クレジット

- 音（BGM・環境音・効果音）：第三者の素材は無い。すべてこのリポジトリのコードで合成したオリジナル。表示の義務のあるクレジットは無い。
- 声：端末の読み上げ（OS・ブラウザの音声）を使う。声のデータはゲームに入れていない・配っていない（端末ごとに違う）。

## 6. 確かめ

確かめの種類：**自動テストだけ**／**実際に音を出力して確かめた**（ページの中で、マスターの後の AnalyserNode と MediaRecorder で取った）／**実機未確認**。
記録の置き場所（作業の時の一時置き場）：`scratchpad/v21/audio/`（下の「記録」）。

  合戦の画面に入ると止める、アプリの切り替えで止めて戻っても読み直さない・隠れている間の台詞をためない、ミュート・音量 0 で読まない、有効にする前は読まない

### 実際に音を出力して確かめた（e2e/audio-check.mjs。開発サーバー・headless Chromium）

音の大きさは、マスター（ミュート）の後の AnalyserNode の RMS（100 ms ごと）。音のファイルは同じ所から MediaRecorder（webm/opus）で取り、ページの中で読み戻して 0.5 秒ごとの大きさを測った。

- **songs**（実時間ではない。ゲームと同じ楽器・楽譜のコードを OfflineAudioContext で描いた見本の音のファイル）：
  3 曲 48 秒ずつ（城下 −19.8 dBFS・急報 −18.3 dBFS・合戦 −15.5 dBFS、割れたサンプル 0）と効果音の見本（足音・荷の作業・きしみ・刃・矢・太鼓・鉦・拍子木・法螺・風）。
- **flow**（描画の省略 `?render=manual`・実時間。入力：タイトル・メニュー・ミュート・つまみ・選択肢・合戦の始め・×2・全軍撤退・続けるは本物のクリック、
  歩くのは本物の W、行送りは本物の Enter、能力は本物の 1 → F。忠勝と話すのは開発用の口（`__game.talk`）、支度で約束に答えた状態は直接状態変更、
  城門の手前へは `__game.teleport`、合戦の結果までは早送り（`__battle.fastForward`）。声は偽の speechSynthesis をページに差し込んで記録）：
  - 曲の移り変わり（はじめからの秒）：0.2 城下（冒頭の町の様子）→ 3.5 急報（使者の到着）→ 18.2 城下（操作の開始）→ 37.0 急報（軍議）→ 49.6 城下（支度）→
    55.2 合戦（出陣の演出）→ 合戦の画面 → 136.8 急報（撤退で帰る演出）→ 145.6 城下（戦後）。
  - 区間ごとの RMS の平均：冒頭 0.133・城下を歩く 0.159・軍議 0.135・合戦 ×1 0.172・×2 0.166・斬り合い 0.181・戦後の城下 0.125。
  - ミュート（本物のクリック）の 2 秒：RMS・最大値とも 0（15 回の記録すべて）。外すと 0.158 に戻る。BGM のつまみ（本物のクリック）で 0 にでき、`koto-sengoku/3d-audio` に書かれた。
  - 切り替えで重ならない：2 曲が同時に鳴ったのはフェードの間だけ（最長 0.82 秒）、3 曲は 0。
