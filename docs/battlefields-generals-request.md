# 次工程の依頼本文：武将・部隊数の拡張と多様な合戦場（2026-09-29 受領・原文のまま）

> 再開時はこの本文を正とする。前提：Version 11 の歴史シナリオと合戦は、利用者がテストプレイして「面白い」と評価している。今の合戦の仕組みは残す。

次の開発目標は、
「武将・部隊数の拡張」と「多様な合戦場」です。

完成版では最低20種類の合戦場を収録する前提で設計してください。

今回はその土台として、
武将6人程度を扱える編成と、
性質の違う合戦場5種類を実装してください。
これを20種類へ拡張しやすいデータ駆動構造にします。

【武将と部隊】

1部隊には、率いる武将を1人設定できるようにしてください。

武将には最低限、
・ID
・表示名
・所属
・部隊での役割
・固有能力
・AIの基本方針
・主人公との関係状態
を持たせます。

現在の家康・本多忠勝・浅井長政をこの構造へ移します。

追加候補として、
酒井忠次
石川数正
榊原康政
を扱えるようにしてください。

ただし年代・所属・役割については確認した史実と
ゲーム用の解釈を区別してください。

酒井忠次・石川数正は、
軍議や部隊指揮で存在感を出せるようにします。
本多忠勝を参謀として扱わず、
前線の主要武将として扱います。

今回は全武将の完成能力を大量に作らず、
既存能力と、新規武将用の仮能力データを
差し替え可能な形にしてください。

【部隊数】

通常の野戦で、
味方6〜8部隊、敵6〜10部隊程度まで
扱える構造にしてください。

最初の5戦場では、この上限をすべて使う必要はありません。

スマホで8部隊を1つずつ操作する負担を考慮し、
複数部隊選択や部隊グループ化を
後から追加できる構造にしてください。

今回はUIを複雑にし過ぎず、
現在の部隊選択と命令方式を維持してください。

【合戦場システム】

戦場ごとのコードを大量に分岐させず、
データから戦場を構築できるようにしてください。

各戦場データには最低限、
・戦場ID
・名称
・地形
・通行可能範囲
・移動速度補正
・視界への影響
・高低差または有利地点
・味方初期配置
・敵初期配置
・援軍出現地点
・撤退地点
・主目標
・副目標
・特殊ルール
を持たせてください。

【今回実装する5種類】

1. 大平原
   基本となる野戦。
   正面、側面、予備隊の使い方を確認する。
2. 河川・浅瀬
   渡河地点を限定する。
   水中または渡河中は移動や戦闘に不利が出る。
3. 丘陵
   高所を取る意味を作る。
   高低差の効果はデータとして調整できるようにする。
4. 森林
   林の中では移動・視界などに影響を与える。
   奇襲や別働隊が使いやすい戦場にする。
5. 山道・峠
   狭い通路のため大軍を同時に展開しにくい。
   少数の部隊でも要所を守れる。

5種類が、
背景の違いだけでなく実際の命令や戦い方を変えること。

【完成版で予定する戦場】

今後、最低でも次の20種類へ拡張できるようにする。

大平原／河川・浅瀬／一本橋／複数橋／丘陵／尾根／森林／山道・峠／谷間／水田／
湿地／村落／寺社／城下町外縁／城攻め前面／包囲された陣／援軍救出／退却戦／夜襲・奇襲／湖・海・河岸

今回は残り15種類を仮のコピーとして作る必要はありません。
5種類を実際に遊べる品質で作り、
残りを同じデータ形式で追加できることを確認してください。

【勝利条件】

毎回敵全滅・本陣撃破だけにしないでください。

戦場データから、
・敵本陣撃破
・地点確保
・一定時間防衛
・味方救出
・指定地点突破
・撤退成功
・援軍到着まで耐える
などを設定できるようにしてください。

主目標と副目標を分けます。

既存の「約束」システムは副目標と共存させ、
合戦の勝敗・副目標・約束の達成を
別々に保存できるようにします。

【今回は行わないこと】

顔・衣服・街の美術改修／全国マップ／20戦場すべての制作／大量の武将追加／装備収集／巨大な育成ツリー／エンジン変更

【確認】

現在のVersion 11の合戦を壊していないこと。

5種類の戦場をそれぞれ通常の操作で開始し、
地形によって戦い方が変わることを確認する。

少なくとも1つの戦場では6部隊以上を動かし、
現在のスマホUIとPC UIで選択・移動・攻撃・防衛・撤退ができること。

勝敗・副目標・約束が別々に記録・保存されること。

既存セーブを壊さないこと。

・各戦場で有効だった作戦
・20戦場への拡張方法
・確認済みと未確認
を報告してください。

この工程では静止画の承認待ちで止まらず、
実装・統合・通し確認まで進めてください。
