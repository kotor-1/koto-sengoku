# テストと確認の一覧

## 実行方法

```bash
npm run check          # 型検査 → 単体テスト → ビルド
npm test               # 単体テストだけ（Vitest。ブラウザ不要）

# ブラウザでの確認（別の端末で npm run dev を起動しておく。出力は e2e-out/）
npm run e2e:desktop    # PC：移動・会話・保存・保存失敗・つづきから・入力解除
npm run e2e:touch      # スマホ相当：スティック・会話・保存・縦画面案内・切り欠き・スクロール
npm run e2e:multitouch # 2 本指（スティック＋ボタン）
npm run e2e:interrupt  # 低 fps・画面の中断・復帰で移動入力が残らない／ゲーム内時間が遅れない
npm run e2e:visual     # 2.5D：解像度・半透明化・前後・間引き・時間帯・8 方向・カメラ・吹き出し
npm run e2e:walk       # 城下を 30〜50 秒歩いて、カメラ〜UI を同時に確認（MODE=phone でスマホ相当）
npm run e2e:shots      # 確認用スクリーンショット（昼・夕・夜・半透明化・城門）
npm run e2e:wedge      # 既知の描画問題の再現（docs/known-issues.md）
npm run e2e:perf       # 表示物の数・テクスチャ容量・パーティクル数・解像度の記録
```

- ブラウザ確認には Chromium が必要。Mac では最初に一度 `npx playwright-core install chromium`。
- 確認先は環境変数 `BASE`（既定 `http://localhost:8080`）。本番ビルドを確かめるなら `npm run build && npm run preview` のあと `BASE=http://localhost:8080`。
- **ブラウザ確認の fps は実機の性能ではない。** 検証コンテナはソフトウェア描画（SwiftShader）で、数 fps〜40fps 程度しか出ない。

## 単体テスト（Vitest）

| ファイル | 確認していること |
|---|---|
| `tests/map.test.ts` | 地図の形・外周が塞がっている・全地域へ歩いて行ける・家臣や高札の隣に立てる |
| `tests/collision.test.ts` | 壁で止まる・すり抜けない・壁沿いに滑る |
| `tests/input.test.ts` | キー・スティックの入力、ボタンの 1 回消費、`releaseAll` |
| `tests/session.test.ts` | 移動・壁・家臣を通り抜けない・会話の開始と終了・背を向けると話せない・地域とフラグ |
| `tests/save.test.ts` | 保存と再開・保存領域なし・容量不足・書き込み確認の失敗・壊れたデータ |
| `tests/render-world.test.ts` | 配置の抽出・8 方向の向き・カメラ・画質の判定・時間帯 |
| `tests/timing.test.ts` | **（今回追加）** 30/60/120fps で同じゲーム内時間の移動距離がほぼ同じ・壁で止まる位置が同じ・10fps 未満の扱い・長い中断後のワープ防止 |
| `tests/interrupt.test.ts` | **（今回追加）** blur・pagehide・pageshow・visibilitychange・画面回転で入力が解除される／中断→復帰後に低 fps の大きな時間差でも動かない |

会話の到達（家臣に話しかけられるか）は `session.test.ts`、移動速度（フレームレート）は `timing.test.ts` と分けている。

## 既存テストを変えたところと理由（確認範囲が狭まっていないか）

### 単体テスト

| ファイル | 変更 | 理由 | 確認範囲 |
|---|---|---|---|
| `tests/render-world.test.ts` の画質判定 | コア数 4 の端末を「低」と判定していた前提を、「メモリが十分なら高」に変更。ケースを追加（コア 2 → 低、端末情報なし → 高、URL・メニュー・自動の優先順） | コア 4 で一律「低」だと、検証コンテナも多くの端末も低画質になっていた。低性能の判定はメモリ（3GB 以下）とコア 2 以下に絞り、実際に遅い場合は描画解像度の自動調整（ResolutionGovernor）で下げる | 広がった（以前の 3 ケースはすべて残し、URL 指定の確認は優先順のテストへ移した） |
| `tests/session.test.ts` ほか core のテスト | 変更なし | — | — |

### ブラウザ確認スクリプト

2.5D 化の途中まで作業用フォルダにあったものを `e2e/` に入れた。そのときまでに変えた点を含めて記録する。

| スクリプト | 変更 | 理由 | 確認範囲 |
|---|---|---|---|
| `regression-desktop.mjs` | 会話の確認を「家臣の手前から 1.2 秒歩いて話す」から「家臣の隣に置いて話す」へ。城下への移動は「2.2 秒押す」から「城下町に着くまで押す」へ | 時間で区切った歩行は検証環境の fps で届く距離が変わり、会話の失敗と移動の失敗が混ざっていた。移動の速さは `timing.test.ts` と `interrupt.mjs` で別に確かめる | 同じ（会話・移動の両方を確認。混ざらなくなった） |
| `regression-touch.mjs` | 「誰もいない場所でスティック＋ボタンを 2 本指」の部分を削除 | 「話す」ボタンは相手が近いときだけ表示する仕様にしたため、誰もいない場所では押せない | 2 本指は `multitouch.mjs` で、ボタンが表示される家臣の隣で確認している（狭まっていない） |
| `multitouch.mjs` | 家臣の隣でスティック＋ボタン。押した表示・会話開始・スティックの指の追跡を確認 | 上と同じ。ボタンを押すと会話が始まり、会話中は移動を止める仕様なので「押しながら歩き続ける」確認はできない | 「ボタンの指を離してもスティックの指は解除されない」は、ポインタのイベント記録（スティックの pointerup がボタンより後）で確認している |
| `walk.mjs` | 時間で区切った経路を、主人公の位置を見て目標地点へ向かう方式に。到達の許容を 12px に。草の揺れの判定をコマ切り替えで見る | fps で歩く距離が変わり、PC 表示とスマホ表示で同じ場所を通れなかった。草は回転をやめてコマ切り替えにしたため | 同じ（8 方向・描画順・半透明化などの判定は変えていない） |
| `visual.mjs` | 決まった時間待つ代わりに、条件が満たされるまで待つ | 検証環境の fps が低いと待ち時間内に変化が終わらなかった | 同じ |
| 各スクリプト | 家臣の座標を (30,11) → (32,10) | 家臣の立ち位置を城門の脇へ移したため | 同じ |
