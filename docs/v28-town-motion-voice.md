# Version 28：歩く城下町・人物と出来事の動き・台詞の音声（設計）

基準：Version 27（版 1791892405-be84・コミット 924c56f。リポジトリ d6ad4c9 は確認用スクリプトと記録だけの追加）。
依頼：ユーザーの試遊評価（軍議の立ち絵と背景は好評。歩く城下町は旧品質、人物の動きと物語の演出が安っぽい、端末の読み上げが棒読み）。
今回の評価対象は **軍議へ入る前の「動く城下町と短い出来事」**。

## 0. 守ること（依頼の条件）

- 維持：軍議の画像（立ち絵・背景・選択肢の配置）、合戦、20 戦場、能力、シナリオの選択と結果、保存、BGM。軍議の立ち絵の大きさ・選択肢の配置は触らない。
- 巻き戻さない：Version 27 以降の変更（d6ad4c9 まで）を消さない・戻さない。
- 素材購入・外注・有料 API の新規利用・ゲームエンジンの変更はしない。
- 新しい歴史イベント・重要な選択は足さない。既存の台詞の文と意味は変えない（声・間・演出だけ）。酒井・石川・忠勝の配役は変えない。
- 視聴の有無（最後まで見た・飛ばした）で兵力・信頼・進行を変えない。
- 保存：既存の保存の鍵（koto-sengoku/save、3d-chapter1、3d-ieyasu1570（/previous・/chapter1）、3d-fields、3d-audio）以外の鍵を足さない。既存の保存を消さない。
- CSP は今のまま（`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' blob:; connect-src 'self'`）。data: URL・WASM は使わない。音は同じ出どころの fetch → decodeAudioData。

- 生成画像を作る機能はこの環境に無い。無いものを生成済みとして扱わない。一覧ポスターの画像を素材として扱わない。
- 公開リポジトリ：原画 ZIP・パックの原画をコミットしない。音声合成の本体・モデルはリポジトリにも配信にも入れない（出来た台詞の音声ファイルだけを配信する）。

## 1. 範囲

1. **歩く城下町**（町の入口の木戸 → 店先 → 兵の詰所の前 → 城門の前の家臣 → 軍議）の 3D 空間そのもの。町全体・全国は広げない。
2. **人物の動き**（主人公の歩き・走り・止まる・向きを変える・待機、町人、家臣と使者）と **出来事の演出**（使者の到着・人物の反応・視線・間）。出陣・帰還は見直すが、評価の中心は 1 の場面。
3. **台詞の音声**：端末の読み上げ（speechSynthesis）を完成形にしない。無料で条件を確かめられる音声合成で、台詞ごとに声・読み・間・話し方を決めた音声ファイルを事前に作って配信する。

評価する一連の場面：**町を歩く（操作）→ 使者の短い急報（出来事）→ 操作へ戻る**。

### 3.2 作り直す物（形から）

- **町家 D の鏡写しをやめる**：同じ正面・同じ小物が路地の両側に並ぶ写し（z 12.9〜19.9、木戸の柵の線にまたがる）を、別の形の建物に置き換える（例：土蔵造りの店、または平入りの小さな商家。木戸の柵の線にまたがらない奥行きにする）。
- **西の空き地（B の南、z 7.6〜16.4）**：荷置き場は残しつつ、通りに面した低い建物（小屋掛けの店・物置）か板塀で通りの西の縁を閉じる。物見櫓と `LOOKOUT` への歩く道は残す。
- **道沿いの建物の正面・側面・軒下・店先**（A・B・D・新しい建物）：
  - 軒下：垂木・出桁・腕木などの軒裏の形、板庇、軒の影が落ちる奥行き。
  - 店先：格子・揚げ見世（ばったり床几）・暖簾（垂れた布の形）・商品の棚と箱・看板（文字は架空の屋号か無地。実在の店名・地名を書かない）。
  - 側面：妻壁・下見板・腰板・壁の下の汚れ。鏡写しや同じ面の繰り返しを避ける。
  - 既存の A・B・D は Blender の作り方（`proto3d/blender/machiya/`・`kit.py`・`blender/lib/mats.py`）で作り直してよい（新しいファイル名で出し、旧 GLB はリポジトリに残す）。
- **接地**：建物の土台石・礎石・犬走り・雨落ち（軒の線の下の砂利の帯）・壁の裾の汚れと湿り。小物（樽・俵・籠・荷車・床几・筵）にも接地の影（地面の焼き込み、または小物ごとの接地の影）。
- **境界**：土の道 ↔ 石の縁 ↔ 側溝の水 ↔ 草・苔、土 ↔ 砂利、塀の裾の草。側溝は石の縁と水面（浅い水・水際の湿った色）を持つ。今ある東の側溝が z 11 で途切れる所・南半分の接地の無さを直す。
- **木と低木**：通りの景色に入る木（柳・松・楓など、形の違う 2〜3 種）と低木・草むらを、道の縁・塀の裾・家の脇に、まとまりと抜けを付けて置く。今のツツジの暗い塊を直す。
- **色だけの箱の小物をやめる**：木戸・柵・物見櫓・小屋・荷車・俵・籠・槍立て・筵・桶を、材質の画像の付いた形（`kit.py` の部品：樽・籠・俵・箱・床几・板塀・石など）へ置き換える。筵は厚みの無い板にせず、編み目の材質と端のほつれ・たわみを持たせる。荷運びの俵は肩に担ぐ大きさ・位置にする（頭を隠さない）。
- **近景・中景・遠景のつながり**：
  - 中景：塀の向こう・路地の奥に見える家並みの屋根（軽い形を並べる）、板塀・竹垣、木立。木戸の外は街道と田畑（あぜ・水の張った田・畑の畝）を、途中で切れた地面の端が見えないように広げる。
  - 遠景：丘・山の重なり（3 段ほど、手前ほど濃く、奥ほど空の色へ溶ける）。霧に溶けて平らな壁に見える今の遠景を直す。
  - 町の外を広げすぎない（見える範囲だけ。歩ける範囲は今の範囲から広げない）。
- **光（人物と背景が同じ場所に見える）**：
  - 西側の家（A・B）の正面がいつも逆光で青黒い問題を直す（太陽の向き・高さ、空の光、地面の照り返しの補い、影の青み）。
  - 人物も建物と同じ影を受け、軒下に入れば暗くなる。足元に接地の影。人物の材質の明るさ・反射を背景とそろえる。
  - 第二章・出陣・帰還・物見でも同じ光で破綻しないこと。

### 3.3 当たり判定・NPC の道・歩ける道を見た目と一致させる

- 当たり判定とカメラ除けは、**形を作った側（Blender の書き出しの meta、または町の配置データ）から作る**。見た目の物ごとに、その物の当たり判定を同じ場所から出す（手で別に書いた箱と、形の位置がずれないこと）。
- 家の当たり判定の二重（scene.json の足元の四角と meta）を 1 つにする。
- 確かめ（`tests/proto3d-town.test.ts`・`tests/proto3d-town-stage.test.ts` を広げる）：
  - 見た目の固い物（建物・塀・柵・木の幹・樽・荷車・櫓の柱など）ごとに当たり判定があり、位置と大きさが形の足元と合う（許す差を決めて確かめる）。
  - 歩ける道：入口 → 忠勝、入口 → 物見、入口 → 両使者、入口 → 休み場の前を、当たり判定を避けて歩ける。
  - 町人・荷運び・使者・家臣・隊列・援兵・負傷兵の道すじが、どの時刻でも当たり判定に入らない。カメラが物の中に入らない。
- 地面の高さ（`ground_height.json`）は新しい地面から作り直す。

### 3.4 重さ

- 町を歩く標準の 6 か所の視点で、1 コマの三角形数・描画命令数（`renderer.info`。手動描画で測る）を Version 27 から大きく増やさない（目安：三角形 +15% 以内。増えるなら、見えない所の形を減らして釣り合わせる：遠い木の葉・人物の形・影を落とす物の選び方など）。
- 配信の容量：新しい町の素材は、今の材質の画像を使い回し（同じ画像はまとめる）、増える分を記録する。1 回の公開の上限（64 MB・255 ファイル。変わったファイルだけ数える）と版全体の上限（256 MB・511 ファイル）に収める。
- この環境の描画は 1 秒に 1 コマに届かない（ソフトウェア描画）。重さは数（三角形・描画命令・画像の大きさ）で比べ、実機の滑らかさはユーザーの試遊で確かめる。

### 3.5 不足する実素材（一度まとめて報告する）

町の作り直しは、手元にある物（Blender の手続きの材質 25 種・`kit.py` の部品・`plants.glb`・家の GLB）で行う。生成画像は手元に無く、作る機能も無い。より良くするために不足する素材は、用途・寸法・内容を一覧にして一度だけ報告する（例：遠景の山並みの横長の絵、木の葉の透過の画像、地面の汚れ・轍・水たまりの重ねる画像、暖簾の柄）。

## 4. 人物の動きと出来事の演出

### 4.1 主人公（操作中）

- 足の運びと実際の移動を合わせる：立ち止まり・歩き出し・方向転換・歩き ↔ 走りの切り替え・壁沿いの移動で、地面に着いた足が滑らない（目安：着いた足の速さ 0.3 m/s 以下。意図した軸足の回転は除く）。
- 向きを変え終わるまで入力を待たせない（押した向きへすぐ動き出す・途中で別の向きへ変えられる）。ただし体の向きは 1 コマで大きく飛ばない（60 コマ/秒で 1 コマ 12° 以内を目安）。大きな方向転換（135° 以上）は、足を踏み替える短い回り込みにする。
- 急な姿勢の変化・過剰な上下動を避ける：待機と歩きの腰の高さの差（今 6〜8 cm）をなくす。歩きの腰の上下の向き（今は逆）を直す。走りの上下は控えめに。
- 足を地面の高さに合わせる（簡単な脚の IK：地面の高さの表から、足首の高さを合わせ、腰を下げる）。
- 待機：呼吸と小さな重心の移り（同じ姿勢で固まらない。大きく揺れない）。
- 歩き・走り・待機の動きの元（`assets-src/hero_v2/build_hero.py` の `frame_pose`）を直して作り直してよい（主人公と町人の GLB の動きの元。旧 GLB は残す）。
- カメラ：後ろから追う。勝手に回らない・揺れない。出来事の後は、出来事の前にプレイヤーが向けていた向き・高さへ戻す（今は出来事の後に真後ろへ戻される：`setHeroPose` が向きを上書きする）。

### 4.2 町人

- 全員を同じ周期で動かさない：歩く速さ（0.95〜1.3 m/s）・歩幅・待機の周期・動きの再生の速さ・始まりの位相を人ごとに変える。
- 道の角で向きが 1 コマで折れない（曲がり角を丸める）。歩き出し・止まりで加速・減速し、足を滑らせない。
- 商人の「お辞儀を続ける」動き（一定の周期で永遠に）をやめる：待機・品物を整える・通りを見る・近くを主人公が通ると軽く会釈する、の間で移る。
- 意味の無い拡大縮小を動きにしない：詰所の兵の「座る」を、縦に潰す（y を 0.7・0.52 倍）のではなく、座った形にする（町だけ。合戦の兵の見た目は変えない）。
- 隊列（出陣・帰還）：同じ列の兵が同じ位相で一斉に上下しない（人ごとの位相・歩幅の違い）。

### 4.3 出来事の演出：町を歩く → 使者の短い急報 → 操作へ戻る

今の第一章の冒頭（`ch1_open`：町の様子 → 使者 2 人の到着 → 忠勝の報告と家康の返事 → 操作）は、操作の前にすべて流れる。V28 では同じ場面・同じ台詞を、次の順に並べ直す（新しい出来事・選択は足さない）：

1. **はじめに（短い）**：町の様子の字幕「元亀元年、徳川家康の城下に、織田と浅井の使者が同じ日に来た。」を、町の入口の主人公へ寄っていく 1 つのカメラの動きで見せ、切らずに肩越しのカメラへつないで操作を渡す（4 秒前後）。
2. **操作**：入口から通りを北へ歩く・走る・見回す。町人が働いている。使者はまだ町にいない（話しかけられる使者は、出来事の後に現れる）。
3. **急報（出来事）**：主人公が通りを北へ進み、決めた線（例：z 6 前後。どの道を通っても城門へ行くなら必ず越える線）を越えたとき、1 回だけ始まる。
   - 織田の使者が南の木戸から走ってくる（足音）→ 主人公が足を踏み替えて振り向く → 使者は減速して止まり、片膝・礼をして急報「徳川殿にも、兵を出していただきたい。」。
   - 浅井の使者が少し遅れて急ぎ足で来て止まり、「主は、徳川殿と手を結びたいと。」。主人公は話し手の方へ顔を向ける（首と目線。体は必要なときだけ回す）。
   - 城門の方から忠勝が歩いて来て、止まってから「殿、軍議を開きましょう。城門の前でお待ちします。」。
   - 家康は短い間を置いて「うむ。皆を集めよ。」。
   - 忠勝は軽く礼をして城門の前へ歩いて戻る（瞬間移動しない）。使者 2 人は町の話せる位置へ歩いていく（着いた所で入れ替えの飛びが見えない）。
   - カメラは 2〜3 の画で、話す人と聞く人を見せる（大きな旋回・ズームを繰り返さない）。
4. **操作へ戻る**：出来事の終わり（または飛ばした時）に、入力とカメラを確実に戻す。カメラは出来事の前の向き・高さへなめらかに戻す。使者と忠勝はまだ歩いていてよい（歩きながら話せる位置へ着く）。

- 飛ばせる（Esc・「スキップ」）。飛ばしたときは、人物を出来事の終わりの位置へ置き（使者は話せる位置、忠勝は城門の前）、声を止め、入力とカメラを戻す。
- 見ても飛ばしても状態（兵力・信頼・進行・保存）は変わらない。出来事は保存に書かない（保存の形を変えない）：「はじめから」で始めた回の中だけで 1 回。「つづきから」・確認用・第二章では起こさない（使者は最初から話せる位置にいる）。
- 出来事の長さは 15 秒前後まで（長いムービーにしない）。字幕の長さは実際の音声の長さ（§5 の一覧）から決める。
- 第二章の冒頭（`ch2_open` の使いの到着）・出陣・帰還も、同じ動きの直し（到着の減速・視線・止まってから話す・瞬間移動しない・兵の位相）を使う。

### 4.4 人物の反応・視線・間

- 話しかけたとき（`faceTalk`）：主人公の向きを 1 コマで回さない（足を踏み替えて 0.3〜0.5 秒で向く）。相手も足を動かして向く。
- 話し手へ顔と目線を向ける（首の骨を回す。限度と滑らかさを付ける）。
- 返答の間：声の終わりから次の話し手の声の始まりまでの間を台詞ごとに決める（例：急報の後、家康が答えるまでに少し間）。

## 5. 台詞の音声

### 5.1 使う音声合成

- **VOICEVOX CORE 0.17.0**（手元で動かす。有料 API ではない）。音声モデル（VVM）・ONNX Runtime・辞書は公式の配布（GitHub の VOICEVOX/voicevox_core・voicevox_vvm・onnxruntime-builder、r9y9/open_jtalk）から取った。リポジトリ・配信には入れない。
- 利用規約（`voicevox_vvm` の TERMS.txt・README の音声ライブラリ利用規約）：商用・非商用で使える。**作品の中に「VOICEVOX:キャラ名」のクレジットが必要**。青山龍星・後鬼などは「企業が携わる形」なら事前確認が必要、No.7・ユーレイちゃん・もち子さんは非商用・ゲーム作品の制限などがあるので使わない。各キャラの詳しい規約ページはこの環境から開けない（ネットワークの制限）ので、ユーザーに確かめてもらう。
- **AivisSpeech は使えない**：エンジンのコードは取れるが、必要な BERT モデル（huggingface.co）と声のモデル（api.aivis-project.com・hub.aivis-project.com）がネットワークの制限で取れない。

### 5.3 台詞ごとの調整（音声の台本）

- 台本：台詞の id ごとに、声・スタイル・読み（AquesTalk 風のカナ。アクセントの位置・句の区切り）・話す速さ・抑揚・高さ・音量・前後の無音・句の間（ポーズの長さ）・強める拍・演技のねらいを書く（`proto3d/voice/script.json` など）。
- 読みは自動の解析に任せず、台詞ごとに書く（例：「殿」が「シンガリ」と読まれる誤りを、カナで「トノ」と指定する）。自動の読みとの違いを記録する。
- 作る道具（`proto3d/tools/voice-build.py`）：台本から WAV を作り、音量をそろえ（ピークと平均の目安）、MP3（モノラル）にして `proto3d/public/voice/` へ。長さ・sha256・字幕の文・声のクレジットを一覧（`manifest.gen.json`）へ書く。手元の音声合成の場所は引数で渡す（リポジトリに入れない）。
- 確かめ：一覧の文と、台詞の表（`voiceLines.ts`）・会話の行の文が完全に同じ。読みのカナが台本どおり。音の長さ・前後の無音・ピークが範囲内。
- 最初のサンプル（第一章の町の出来事と城門の前の会話）：

### 5.4 ゲームの中で流す

- 音声ファイルは fetch → `decodeAudioData` → 声のバス（BGM を下げる）で流す。同じ出どころの fetch なので CSP は変えない。
- 字幕・会話の行が出たときに、その行の音を流す。行を送った・選択肢を選んだ・会話を閉じた・飛ばした・メニューを開いた・情勢を開いた・合戦へ入った・アプリが隠れた（visibilitychange・pagehide・blur）ときは止める。戻っても前の行の音を後から流さない（遅れて届いた音は捨てる）。同じ行の音を重ねて流さない。
- 新しい声の無い行は無音（旧読み上げで自動的に埋めない）。
- 設定：音の設定に「声の種類」（新しい声／端末の読み上げ（旧））を置く。保存は今の `koto-sengoku/3d-audio` の中（新しい鍵は作らない）。URL の `?voice=tts` で旧読み上げ。
- クレジット：音の設定の画面に「音声：VOICEVOX:（使った声の名前）」を出す。`docs/third-party-assets.md` にも書く。
- 演出の字幕の長さは、実際の音の長さ（一覧の秒数）を使う（今の拍の数からの見積もりをやめる。見積もりは音の無い行だけ）。
