## Mac で起動する手順

```bash
# 1. 取得（初回）
git clone https://github.com/kotor-1/koto-sengoku.git
cd koto-sengoku
git checkout claude/friendly-hopper-7hijta
# 2 回目以降は: git checkout claude/friendly-hopper-7hijta && git pull

# 2. Node.js 22.12 以上を確認（足りなければ Homebrew などで入れる）
node -v

# 3. 依存を入れる（package-lock.json どおり）
npm ci

# 4. 本番用にビルドして、同じ Wi-Fi から開けるように配信
npm run build
npm run preview:lan
```

`preview:lan` を実行すると、次のような表示が出る。

```
➜  Local:   http://localhost:8080/
➜  Network: http://192.168.1.23:8080/    ← スマホではこちらを開く
```

- Mac のブラウザでは `http://localhost:8080/?fps`。
- macOS が「受信接続を許可しますか」と聞いたら許可する。スマホから開けないときは「システム設定 → ネットワーク → ファイアウォール」を確認する。
- 開発中の画面（変更が即反映）で見たいときは `npm run dev:lan`（本番ビルドとは速さが違うので、性能の記録は本番ビルドで取る）。

## スマホで開く手順

1. Mac とスマホを **同じ Wi-Fi** につなぐ。
2. スマホのブラウザで `http://<Mac の Network アドレス>:8080/?fps` を開く（例 `http://192.168.1.23:8080/?fps`）。
3. 端末を横向きにする。
4. 左下に fps などの表示が出る（`?fps` を付けたとき）。

| 左下の表示 | 意味 |
|---|---|
| `58 fps（2 秒平均 57）` | いまの fps と、直近 2 秒の平均（起動直後の約 5 秒は「計測中」） |
| `画質 高：自動（メモリ 8GB・コア 8）` | 画質と、そう決まった理由。`端末情報なし→高` は iOS Safari などで端末情報が取れない場合 |
| `描画 1688×780px（×2）` | 実際に描いている画素数と倍率（遅いと自動で ×1.5 → ×1.25 → ×1 に下がる） |
| `表示物 170・素材 20.1MB` | いま表示中の物の数と、作った画像の合計容量 |
| `準備完了 1435ms（素材生成 947ms）` | ページを開いてから操作できるようになるまでの時間と、そのうち画像を作るのにかかった時間 |

### 画質を変えて比べる

- メニューの「画質：自動／高／低」を押すと切り替わり、**再読み込みで反映**される（端末に覚える）。
- URL に `?q=low` や `?q=high` を付けると、そちらが優先される。

### 不具合を調べるとき

- iPhone：「設定 → Safari → 詳細 → Web インスペクタ」をオンにして、ケーブルで Mac につなぎ、Mac の Safari の「開発」メニューから開く。
- Android：「開発者向けオプション → USB デバッグ」をオンにし、Mac の Chrome で `chrome://inspect` を開く。
- 木が三角に欠けるか：`?rotsway` を付けて開き、城下の東（川の橋の東側）の木を見る（`docs/known-issues.md`）。
