# 基本方針

## 目的

戦国時代を舞台にした 2D 探索型 RPG の土台を作る。第 1 号試作では「歩いて、話して、保存して、続きから遊べる」ことを、Mac とスマホの両方で成り立たせる。

## 対応目標

- iPhone の Safari、Android の Chrome、Mac のブラウザ（Safari / Chrome）。
- スマホは **横画面** が基本。縦画面のタッチ端末では「横向きに」の案内を出し、操作を止める。

## 今回作るもの / 作らないもの

作る：見下ろし型の探索画面、城門・城下町・街道の小マップ、主人公 1 人の直接操作、会話できる家臣 1 人、建物・壁の当たり判定、追従カメラ、スマホ用スティックとボタン、キーボード操作、日本語の短い会話、端末内保存と再開。

作らない：戦闘、全国地図、武将選択、外交、複雑な歴史分岐、課金、オンライン対戦、クラウド同期、オフライン対応（Service Worker）。

## 設計の決まりごと

### 1. ゲームの状態と画面表示を分ける

| 層 | 場所 | 役目 | 依存してよいもの |
|---|---|---|---|
| 状態・ルール | `src/core` | 位置・向き・フラグ・会話の進行・当たり判定・保存形式 | なし（純粋な TypeScript） |
| 描画 | `src/render` | `GameSession` を読んで Phaser の絵を合わせる | core（読むだけ）, Phaser |
| UI | `src/ui` | 文字・枠・ボタンの表示 | なし（App から表示内容を受け取る） |
| 入力・ブラウザ | `src/platform` | キーボード・タッチ・スクロール防止・画面回転 | core の `InputState` |
| つなぎ | `src/app.ts` | 入力 → `session.step()` → 表示 | すべて |

- 状態を書き換えるのは `GameSession.step()` だけ。描画側は読むだけ。
- core は Phaser も DOM も import しない。そのため Node 上の Vitest でそのままテストできる。

### 2. 入力

- 入力は DOM（Pointer Events / KeyboardEvent）でまとめて扱い、Phaser 自身の入力機能は使わない。
- タッチのスティックとボタンは、指ごと（pointerId）に追いかけるので同時に使える。
- 移動入力は次のときに必ず解除する：指を離した／タッチがキャンセルされた／ポインタの捕捉が外れた／ウィンドウのフォーカスが外れた／タブやアプリを切り替えた（visibilitychange・pagehide）／画面が回転した／縦画面になった／メニューやタイトルに移った。
- 解除後は、同じ指を動かし続けても移動は再開しない（触り直しが必要）。
- キーを離したときは状態にかかわらず解除する。Cmd を離したときも全解除（Mac で keyup が届かない問題への対策）。

### 3. スマホの画面

- `viewport-fit=cover` で全面表示し、操作部品と文字は `env(safe-area-inset-*)` の分だけ内側に置く。
- ページ全体を `position: fixed` にし、`touch-action: none`・`touchmove` の `preventDefault`・iOS の `gesture*` 抑止で、スクロール・ピンチ拡大・ダブルタップ拡大・長押しメニューを止める。
- 会話枠は「話す」ボタンと重ならない幅にする。

### 4. 保存

- 端末内（`localStorage`）にだけ保存する。クラウドには送らない。
- 書き込んだ後に読み戻して一致を確かめ、確かめられたときだけ「保存しました」と表示する。
- 失敗（保存領域が使えない・容量不足・確認できない）はそのまま失敗として理由とともに表示する。成功したように見せない。
- 読み込み時は形式・値の範囲を検査し、壊れたデータでは始めない。位置が壁の中なら初期位置に戻す。
- 保存形式には `version` を入れる。形式を変えたら版を上げ、古い版の扱い（変換するか捨てるか）を決める。

### 5. 素材

- 有料素材は使わない。今は `src/render/textures.ts` でコードからドット絵を描いている。
- 本番素材に替えるときは、テクスチャのキー名（`tiles`・`hero` など）とフレーム名を保てば、描画以外は変えずに済む。

### 6. 地図の直し方

- `src/core/map.ts` の `MAP_ROWS` が地図そのもの（1 文字 = 16px のタイル）。文字の意味は同じファイルの `TILES` にある。
- 直したら `npm test` を実行する。行の幅・外周が塞がっているか・初期位置から全地域へ歩いて行けるか・家臣や高札の隣に立てるかを検査する。

## 確認の決まりごと

- 変更したら `npm run check`（型検査・テスト・ビルド）を通す。
- 実機で確かめていないことは「確認済み」と書かない。自動テストやブラウザのエミュレーションで確かめたものは、そう明記する。
