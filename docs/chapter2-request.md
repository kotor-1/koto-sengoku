【1. 判断待ち事項】

■ 正面突破の敗北を固定したテスト
「この台本が必ず負ける」ことを、
機能の必須合格条件にしないでください。

地形効果、目標判定、移動や命令の正常動作と、
作戦別の勝敗・損害・所要時間の比較を分けます。

目標を無視した手順の失敗確認まで削除する必要はありません。
正面攻撃を勝たせるためだけのゲーム数値変更もしません。

■ 確認中に忠勝の能力が意図せず発動する2か所
確認手順を修正してください。
移動が目的なら、現在の「移動先指定」などを使い、
意図した命令になったことと、
能力使用回数が減っていないことを確認してください。

その2経路は、意図しない能力を使わず再確認します。
能力なしで同じ結果にならなければ、その差を記録してください。
成功に合わせてテストを緩めないでください。

■ 今回変更しないもの
移動命令で離脱する部隊への追撃・守護の適用拡大、
守備区域の敵の射撃への反応は、今回は実装しません。
判断済みの保留事項として記録してください。

確認コードだけの変更なら、それだけの公開更新は不要です。

【2. 第二章の目的】

第一章を終えると、そのセーブの続きとして第二章へ進めるようにします。
独立した第二章デモや、もう一度選び直す別シナリオにはしません。

第一章の協力方針、合戦結果、損害、
人物関係、約束の結果、獲得した支援を引き継ぎます。

第一章の結末画面は削除せず、
章の区切りとして表示した後に「第二章へ進む」を追加してください。
既に第一章を終えたセーブからも進めるようにしてください。

【3. 第二章の内容】

第一章直後の、分岐した世界での出来事を描きます。
特定の史実の合戦を正確に再現したものとは表示しません。
未確認の史実を補って断定しないでください。

3方針それぞれに主要な任務を1つ用意します。

A：織田との協力を続けた
協力軍の撤収や退路の支援を求められる。
既存の一本橋・退却戦などから、適した戦場を1つ使う。

B：浅井との協力を選んだ
浅井側の部隊を救援する。
既存の援軍救出・包囲された陣などから、適した戦場を1つ使う。

C：自領の防衛を優先した
領内の防衛と、残存兵力の使い方を決める。
既存の村落・城下町外縁などから、適した戦場を1つ使う。

各方針に2戦ずつ作る必要はありません。
まず3つの主要任務で、第二章の開始から戦後・章の区切りまでつなぎます。

流れ：
第一章の結果確認
→ 城下で家臣と会話
→ 軍議と今回の判断
→ 出陣
→ 合戦
→ 戦後
→ 第二章の区切り

【4. 結果の引き継ぎ】

方針だけでなく、勝利・敗北・撤退と約束の結果も反映する。

・損害は次の兵力や回復条件に反映する。
・信頼は会話だけでなく、支援や条件にも反映する。
・約束を守って得た援兵を、二重に加算しない。
・約束を引き受けなかったことと、破ったことを混同しない。

第一章で損害が大きい場合でも、必ず進める道を用意する。
ただし、無条件の全快や無料の大量補充で結果を消さない。

兵力が少ない場合は、
回復の代償、支援条件、初期配置や主目標の調整などで対応する。
必要な部隊数が出陣可能数を超えて、開始時から達成不能にならないこと。

存在しない、敵対している、出陣していない武将を、
自動的に味方や救出対象として配置しないこと。

【5. 戦場の利用】

演習用の戦場データを直接書き換えず、
地形・経路・目標の仕組みを再利用する。

物語側で登場部隊、所属、初期兵力、支援、
救出対象や脱出対象を設定できるようにしてください。
戦場の表示名や説明にも、その内容を反映します。

演習の結果とキャンペーンの結果を混ぜないでください。
20戦場すべてを第二章に登場させる必要はありません。

【6. 保存】

既存の第一章・演習・架空シナリオの保存を保護する。
第二章への移行、補充、支援、戦後処理は
再読み込みや連打で二重適用されないこと。

第一章から再開しても、
第二章途中から再開しても、正しい進行に戻ること。
保存の移行に失敗した場合は、元データを消さないこと。

【8. 確認と公開】

通常の画面操作で合戦・戦後・章の区切りまで通してください。

同じ方針でも、第一章の結果が異なると
兵力・支援・会話などが変わることを比較してください。

損害の大きいセーブ、約束を破ったセーブ、
約束を引き受けなかったセーブでも進行可能か確認します。

通常入力、早送り、直接状態変更、実機確認を区別して報告してください。
必要な回帰確認は、変更の影響範囲を整理して行ってください。

旧版へ戻せる状態を残して確認用URLへ反映し、
