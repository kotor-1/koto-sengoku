### 3. 人物と建物の 3D 素材を何から用意するか

- 外部の素材サイトは、この作業環境のネットワークの決まりで使えなかった（接続を拒否：Poly Haven、Kenney、Quaternius、OpenGameArt、Sketchfab、Mixamo）。通るのは npm と GitHub の生ファイルだけ。
- GitHub の glTF 見本（Khronos の CesiumMan など）は、現代の西洋風の人物・機械で、和風のセミリアルに合わない。**利用条件が明確で、和風の人物・建物として使える外部素材は、ここでは用意できなかった。**
- そこで今回は、**人物・建物・木をすべてこの試作のコードで 3D の形として作った**（`proto3d/src/assets/`）。2D の画像を板に貼ったものではない。
  - 作った形は GLB（glTF）に書き出し（`npm run proto3d:models`）、ゲームは GLTFLoader で読み込む。**外部で作ったモデルに替えるときも、同じ名前の GLB を置けば読み込める**（読み込みの仕組みは本物の素材と同じ）。
- 無断の購入、利用条件が分からない素材の採用はしていない。

### まず、差し替えが必要な素材（外部素材が手に入った場合）

今回は外部素材を入手できなかったため（下の「入手できていない素材」）、手元のコードで描いた素材を直した。ただし次のものは、**コードで描く方法では「模型らしさ」が残る**ので、条件に合う外部素材が用意できれば差し替える対象とする。

| 対象 | いまの素材 | 手描きのままでは残る問題 | 差し替えの優先度 |
|---|---|---|---|
| 人物の形と服（若殿） | コードで組んだ筒の組み合わせ＋骨 18 本 | 体の線・布の厚み・しわが「形の式」の範囲にとどまる。手の指・顔の立体がない | **高** |

### 材質で直したこと（町家・道・草地）

「全体にノイズをかける」「強い光やぼかしで隠す」はしていない。汚れ・傷みは、理由のある場所（軒下・雨の当たる面・地面の近く）にだけ、頂点色で少しだけ付けた。光の設定（日差し・空の照り返し・霧）は改修前と同じ。

| 材質 | 改修前の問題 | 直したこと |
|---|---|---|
| 木（古材・弁柄・白木） | 梁の木目が横倒し（材の長さと直角）。木目が太く波打ち、どの材も同じ模様 | 木目が必ず材の長い方向に走るよう、面ごとに UV を振り直した（柱は縦、梁・板は横）。細い年輪の線・晩材の濃い筋・まれな節を描き、画素ごとに粗さを変えた（筋はややつや、面は粗い）。色を古材（焦げ茶）・弁柄（赤錆色）・白木（明るい灰茶）ではっきり分けた |
| 漆喰 | 紙のように平らで白い | こての流れと細かい砂粒の凹凸（法線）を付け、粗さを 0.9〜0.97 に。色はわずかに黄みの白 |
| いぶし瓦 | 青っぽく、プラスチックのようなつや | 灰色を落ち着かせ、つやを 0.38〜0.7 の範囲でまだらに。瓦 1 枚ごとの色の差と、ごく薄い雨の筋。丸瓦の列にも列ごとの色の差 |
| 土の道 | 同じ斑点が細かく繰り返して見える | 小石の粒の位置・大きさを格子ごとにずらし、上からの光の陰を付けた。轍（2 本の暗く滑らかな筋）・中央の盛り上がり・大きなむらを頂点色で付け、6m ごとの繰り返しを崩した |
| 草地 | 平らな一色の緑 | 短い葉を 26,000 本描き重ねた絵と、そこから作った凹凸・粗さ。1 枚の中に大きなむらは入れず（3.5m ごとに同じむらが並ぶため）、大きなむらは地面の頂点色（周期なし）で付けた。道の縁 0.9m は踏まれて黄ばむ。草むらは根もとを暗くして地面になじませた |
| 汚れ・傷み（理由のある所だけ） | なし | 柱・腰の板・格子の下端：雨の跳ね返りで 30% ほど暗く（地面から 0.55m まで）。横と裏の漆喰：軒下から下へ薄い雨筋（7〜8%。軒の深い表の 2 階は 3.5%）。庇の軒先の真下に雨落ちの小石の溝 |
| 形の直し | 庇を支える腕木が庇の瓦を突き抜けていた | 腕木を庇の下に収めた。横・裏の腰は縦の板張り（約 18cm 幅、1 枚ごとに色の差） |

| 項目 | 改修前 | 改修後 |

| 袴の襞 | 波形のゆるい凹凸（折り目に見えない） | 前 5 本・後ろ 2 本の襞を、折り山が鋭く谷がなだらかな段で作った。襞は腰から脚へ続き、下へ行くほど開く |

| 見え方 | 城門・町家・松・道がまとめて入る。人物は小さく（身長で画面の約 1/8）、服や動きは分かりにくい | 町家の表と人物が中心。人物は身長で画面の約 1/5 になり、服の色分け・袴・歩きの動きが分かる。城門は画面の端 |

- 人物と建物の大きさの比は、どちらの画角でも変えていない（同じモデル・同じ縮尺）。
- **合戦の見下ろしのカメラとは別に考える。** 合戦は別の地図で部隊を指揮するので、広く高い視点が要る。ここで比べたのは探索（武将本人を操作する）用の画角だけ。
- 決めていない：探索の既定の画角をどちらにするか（ユーザーの判断）。
