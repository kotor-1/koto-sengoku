# 既知の問題

## 1. 回転した画像の一部が別の絵で描かれる（木が三角に欠ける）

| 項目 | 内容 |
|---|---|
| 状態 | **検証環境で再現。画像を回転させない回避策で解消。根本原因は未確定。** |
| 見え方 | 揺れる木の葉の部分が、四角形の対角線で切ったように三角に欠け、そこに地面の模様が見える |
| 確認した環境 | クラウドの検証コンテナの Chromium 141（Playwright 1.56 同梱・ヘッドレス）＋ SwiftShader（ソフトウェア描画の WebGL）。Phaser 4.0.0 と 4.2.1 の両方 |
| 実機 | **未確認**（iPhone Safari・Android Chrome・Mac のブラウザのいずれでも、起きるか起きないかを確かめていない） |

### 分かっていること

- 画像に回転（rotation）を付けると起きる。回転を 0 にすると起きない。
- 回転角が小さくても（0.012 rad）起きる。毎フレーム角度を変えなくても、固定の角度で起きる。
- Phaser の設定 `render.maxTextures` を 1 にすると起きない。8 では起きる。
  → 複数のテクスチャを 1 回の描画命令にまとめる処理と、回転した四角形の組み合わせで起きている可能性が高い。
- 少数の木だけを回転させた単純な画面では再現しなかった。実際の探索画面（多数の種類のテクスチャが混ざる）で再現する。
- 左右反転（flipX）は関係しなかった。

### 分かっていないこと（根本原因は未確定）

- Phaser 本体の不具合なのか、SwiftShader（ソフトウェア描画）の不具合なのか、両方の組み合わせなのか。
- 実機の GPU でも起きるのか。

### 回避策と適用範囲

画像を回転させない。表示の結果が同じになるよう、次のように置き換えた（`src/render/WorldScene.ts`）。

| 対象 | 以前 | いま |
|---|---|---|
| 木の揺れ | 根元を中心に回転 | 根元を基準に横幅をわずかに伸び縮み ＋ ごくわずかな横ずれ |
| 草むらの揺れ | 根元を中心に回転 | 起動時に「傾けた絵」を 7 コマ作り、コマを切り替える |
| 人物の伸びる影 | 影の画像を光の向きに回転 | 起動時に回した影の絵を作って使う（Canvas 上で 1 回だけ回す） |
| 煙・落ち葉の粒子 | 回転つき | 回転なし（落ち葉は横の伸縮でひらひら感を出す） |

新しく画像を追加するときも、回転（`setRotation`・`rotation`・粒子の `rotate`）は使わない（`docs/art-direction.md` にも記載）。

### 再現・確認の方法

```bash
npm run dev            # 別の端末で
npm run e2e:wedge      # e2e-out/ に 3 枚出力
```

| 画像 | URL の指定 | 検証環境での結果 |
|---|---|---|
| `wedge-default.png` | なし（回避策あり） | 欠けない |
| `wedge-rotsway.png` | `?rotsway`（以前の回転で揺らす） | 欠ける |
| `wedge-rotsway-maxtex1.png` | `?rotsway&maxtex=1` | 欠けない |

実機では、同じ URL（例 `http://<Mac の IP>:8080/?rotsway`）を開き、城下の東（川の橋の東側）の木を見る。

- `?rotsway` … 回転で揺らす（確認用。既定は無効）
- `?maxtex=N` … Phaser の `render.maxTextures` を N にする（確認用）

### 回避策を外してよい条件（将来）

次のすべてを満たしたら、回転による揺れに戻すことを検討してよい。

1. 実機（iPhone Safari・Android Chrome・Mac の Safari と Chrome）で `?rotsway` を開いても欠けない。
2. 使う Phaser の版で、検証環境の `npm run e2e:wedge` の `wedge-rotsway.png` が欠けない（Phaser 側で直った）。
3. 1・2 のどちらかを満たさない場合は、回避策を続ける。`maxTextures: 1` は描画命令が増えるので、回避策としては使わない。

## 2. 起動直後・タブ復帰直後にゲームが遅く進む（修正済み）

| 項目 | 内容 |
|---|---|
| 状態 | **修正済み**（2026-09-24、`src/render/createGame.ts` の `fps.panicMax: 0`） |
| 内容 | Phaser は起動直後とタブ復帰直後の 120 フレームの間、1 フレームの経過時間を 60fps 相当（16.7ms）に切り詰める。30fps の端末では約 4 秒、低 fps ではさらに長く、主人公がゆっくり動いていた |
| 見つけ方 | CPU を 6 倍遅くしたブラウザで、1 秒あたりの移動距離が期待値（約 60〜76px）に対して約 13px しかなかった |
| 確認 | `npm run e2e:interrupt` の「低 fps でもゲーム内時間が実時間どおり進む」。修正後は 7〜10fps で 1 秒あたり 68〜76px |
| 安全策 | 大きすぎる経過時間は core 側で 1 フレーム 0.1 秒に抑えている（`MAX_STEP_SEC`）。10fps を下回る端末では、ゲームは実時間よりゆっくり進む（ワープを防ぐための意図した動き） |
