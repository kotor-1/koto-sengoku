# Version 24：会話・軍議の選択肢を台詞の枠に隠さない（狭い画面）

依頼（2026-10-09）：Version 23 を比較の基準に残し、追加の対応は「縦向きの画面で台詞の枠が軍議の選択肢 C を隠す」問題だけ。
文字（台詞 15px・16px）と顔を縮めずに、会話と軍議の表示領域・スクロールを直して、すべての選択肢と決定・戻る操作に届くようにする。
`?art=old` にも同じ直しを入れてよい（過去の表示は公開先の版の履歴で残る）。合戦・地面・顔の大きさ・高い解像度の絵は変えない。

## 何が起きていたか（Version 21〜23。同じ入力で測った）

選択肢の並び（`.g-choices`）は画面の下から決まった高さ（`bottom: 安全域 + 122px`、高さ 430 以下は 110px）に置き、
台詞の枠（`.g-dialog`）は画面の下に置いて上へ伸びる。台詞が 3 行になると枠の上端がその高さを越え、並びの下の端を隠す。

- **縦向きのスマホ**（360〜412 幅）：軍議の方針の行（3 行の台詞）で、枠が選択肢 C の下 23.6px を隠す（C の 2〜3 行目の説明）。
  第二章の城門の忠勝（「もう少し話を聞いて回る」）・第二章の軍議の判断も同じ。第二章の補充（石川。選択肢 4 つ・長い説明）は
  360×640・375×667 で並びの上の端が画面の外（−138px・−93px）へ出て、最初の選択肢「待つ」が押せない。360×780 でもメニューのボタンが最初の選択肢にかかる。
- **横向きのスマホ**でも、同じ「選択肢が隠れる・押せない」所があった：568×320・640×360 の軍議の方針の A に詳しく見る・メニューがかかる
  （568×320 は A の 29% が隠れる）、約束の「引き受ける」にメニューがかかる、第二章の補充の最初の選択肢が画面の上へ出る
  （568×320 は「待つ」が全部画面の外、667×375・640×360 も一部）、844×390 でもメニューがかかる。
- どれも顔あり・`?art=old` で同じ（Version 21 からある）。台詞の枠が選択肢を隠す行では、Version 23 の顔は出していなかった。

測り：`e2e/dialog-choices.mjs`（ACT=measure）。360×640・360×780・375×667・390×844・412×915・768×1024・844×390・667×375・568×320・
640×360・1280×720・1920×1080 の 12 の大きさ × 顔あり・旧表示 × 第一章・第二章、選択肢の出る 13 の場面（城門の忠勝・軍議の方針・確かめ
（それで決める／考え直す）・改めて・約束・城門の出陣・戦後・第二章の城門の忠勝・軍議の判断・確かめ・補充・戦後）。
選択肢の隠れは、ページの中で選択肢の四角に 4px ごとに `elementFromPoint` を当てて数えた（角の丸みの外は数えない）。

## 直し方（`proto3d/src/ui/choiceFit.ts`・`ui.css`・`ui/view.ts`）

- **かからない画面は何もしない**：CSS のままの並びが、台詞の枠にも、並びの上に描かれる部品（詳しく見る・メニュー）にもかからず、
  画面の上の端からも出ていなければ、並び・台詞の枠に class も style も付けない（Version 23 と同じ DOM・同じ四角）。
  並びの下に描かれる物（軍議の見出し・目的の札）にかかるだけでは動かさない（隠れるのは選択肢ではないので）。
- **かかる時だけ収める**（class `g-fit`）：並びの下端を「台詞の枠の上端 − 12px」に、上は「上の部品の下端 + 8px」までにする。
  境は毎回、本物の四角（台詞の枠・軍議の見出し・詳しく見る・メニュー・目的の札・並び）から求め、CSS の変数（`--g-choices-bottom`・
  `--g-choices-max`）に入れる。1 行でも何行の台詞でも、安全域があっても同じ。上の部品は、並びと左右が重なる物だけ数える。
  見出し・目的の札を避けて入りきらず、見える高さも 192px より低い（低い横長の画面）ときだけ、見出し・目的の札の上も使う（Version 23 と同じく並びの後ろ）。
- **入りきらなければ並びの中だけを縦に動かす**（class `g-scroll`）：`overflow-y: auto`・`overscroll-behavior: contain`（ページ・3D の場面へ伝えない）・
  `touch-action: pan-y`。`g-scroll` はほかの動く欄（タイトルの一覧・メニュー・結末）と同じ印で、`main.ts` のページ全体の touchmove の抑止から外れる。
  - 端の薄れ（`mask-image`。その先に選択肢がある側だけ）と、小さな札「▲ 上にも選択肢」「▼ 下にも選択肢」（押せない・読み上げない）で続きを示す。
  - 最初に選ばれている選択肢が見える所から始める（第二章の補充・約束は最後の「少し考える」が選ばれているので、一番下から）。
  - ↑↓（W／S）で選ぶと、選んだ物が端の薄れにかからず見える所まで並びが動く。数字のキー・Enter は今までどおり。
  - 選んだ印の外の輪（2px）は並びの端で切れるので、動く並びの間だけ内側の輪にする（選択肢の位置・幅は変えない）。
- **それでも並びの高さ（96px）が取れない、とても低い画面だけ**：台詞の欄の高さを（2 行分は残して）縮め、台詞の中を動かせるようにする
  （class `g-text-fit`）。字は小さくしない。測った 12 の大きさでは起きない。
- 画面の大きさ・向きが変わったら同じフレームのうちに、台詞の枠・選択肢の大きさが変わったら（字の読み込み）次のフレームで測り直す（ResizeObserver）。並べ方が変わったら台詞の枠の顔も測り直す
  （`DialogFace.relayout`）。上の画面（メニュー・情勢・見直しの演出）から戻った時も測り直す。
- 台詞の字（縦長 16px・高さ 430 以下 15px）・字の間・行の高さ・台詞の枠の位置と幅・選択肢の字と幅・顔の大きさは変えない。

## 入力の守り（`ui/guard.ts`・`ui/dom.ts`）

- 並びが動かない時は今までどおり、選択肢は押した瞬間（pointerdown）に決まる（Version 23 と同じ）。
- 並びが動く間だけ、選択肢は指・マウスを離した時（pointerup）に決まる（`onPress` の `tapWhen`）。決まるのは「たたき」だけ（`TapTracker`）：
  - 押し始めから 10px（`TAP_SLOP_PX`）より動いた押し（縦になぞった・横へずらした）は決めない。
  - ブラウザが並びを動かし始めた押し（`pointercancel`）、押している間に並びが動いた押しは決めない。
  - 並びが動いて 150ms（`SCROLL_SETTLE_MS`）のうちに始まった押し（動いている並びを止める押し）は決めない。
  - 押している間の動き・離すのは押したボタンに集める（`setPointerCapture`）。
  - 会話が一番上でない間（押したまま別の指でメニュー・Esc・M・J で上に画面を開いた）は、離しても決めない（`ui/view.ts` の選択肢の押し）。
    離すのは押したボタンに届くので、見直しの前は開いた画面の下で方針・約束・補充が決まっていた（下の「見直しの後の直し」）。
- 出たばかりの選択肢の見張り（350ms）と行送りの見張り（140ms）はそのまま。離した時に決める押しは、押し始めの時刻で見る
  （押し始めが見張りの中なら、離したのが後でも決まらない。押している間にメニューが閉じて出直したら決まらない：`InputGate.tap`）。
- 選択肢の出ている行では、台詞の枠・並びの隙間をなぞっても会話は進まない（最後の行なので進む先が無い。今までどおり）。

## 見直しの後の直し（2026-10-09）

見直し 2 回（どちらも本物の入力・開発サーバー）で、高い重さの誤りは無く、中くらいの誤りが 1 つあった。直した。

- **動く並びの選択肢を押したまま、上に画面を開いて離すと、その下で決まっていた**（Version 24 で入った誤り。Version 23 は押した瞬間に決まるので起きない）。
  動く並びでは選択肢を離した時に決めるが、押したまま別の指でメニューを押す・Esc／M・J で上に画面（メニュー・情勢）を開いてから離すと、
  離すのは押したボタンに届き（`setPointerCapture`）、選択肢の見張り（`choiceGate`）は上の画面が閉じるまで出直さないので、
  開いた画面の下で方針・約束・補充が決まり、次の会話がメニューの上に出ていた。
  - 直し：会話が一番上でない間は、選択肢を決めない（`proto3d/src/ui/view.ts` の選択肢の押し。1 行）。押したまま上の画面を開いて閉じてから離した押しは、
    今までどおり `InputGate.tap` が受け付けない（押し始めが出直しより前）。
  - 確かめ：`e2e/dialog-choices.mjs`（ACT=verify）に、動く並びで選択肢を押したまま Esc・J（軍議）・別の指でメニュー（タッチ）を開いて離し、
    上の画面が一番上のまま・会話の層が 1 つのまま・閉じると同じ会話・同じ行・同じ選択肢、を確かめる所を足した。
    直す前の 97e7b26 では 360×640 の軍議で方針 A（織田）が決まって合わず（Esc でメニューを開いた下で `council.confirm.oda` が始まった）、直した後は合う。
- 残した小さなこと（見た目・測った大きさの外。どれも選択肢は押せる・↑↓ で選べる）：
  1. とても低い画面（高さ 300px くらいより低い。例 568×270）：並びの見える高さが選択肢 1 つと上下の端の薄れ（24px ずつ）より低く、真ん中の選択肢は

     直すなら、札を並びの右の端に寄せ、選択肢が見える高さより高い時は薄れを狭める（`choiceFit.ts` の `revealScrollTop`・`placeCues`、`ui.css` の `.g-choices-cue`）。

     `.g-scroll` を足しても動かなかったという見直しの記録もあり、原因は詰めていない）。測ったどの大きさ（568×200・640×260・667×300・320×480 まで）でも、この決まりは働かない。
